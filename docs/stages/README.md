# 阶段实施记录

## 1. 目的

本目录按阶段保存“计划与实际发生了什么”的长期记录。路线图描述未来方向，实施记录描述真实修改、验证结果、限制和交接信息。

当前已完成 `stage-00.md` 和 `stage-01.md`。只有阶段实际实施后才创建对应记录，不能提前填写虚构结果。

## 2. 文件命名

```text
stage-00.md
stage-01.md
...
stage-13.md
```

如某阶段内部拆成检查点，仍使用同一个主记录，并在内部按 `8A`、`8B` 等小节记录，除非学习者确认改变主路线编号。

## 3. 每阶段强制同步清单

完成任何阶段后必须：

- [ ] 更新 `../architecture.md` 的当前架构、流程和限制；
- [ ] 更新 `../stage-specification.md` 的阶段状态和验收摘要；
- [ ] 创建或完成当前 `stage-XX.md`；
- [ ] 更新 `../troubleshooting.md` 中新增的实际问题；
- [ ] 必要时在 `../decisions/` 新增 ADR；
- [ ] 更新 `../README.md` 的当前里程碑；
- [ ] 记录 Git commit 和 tag，未创建时明确说明；
- [ ] 检查文档路径、术语、命令、配置与实际代码一致；
- [ ] 停止并等待下一阶段明确确认。

## 5. 记录原则

- 实施记录必须在真实实现过程中更新，不在结束后凭记忆补写全部细节。
- 测试结果写明实际运行范围，不用“应该通过”。
- 未执行手动验收时写“未执行”，不能推断成功。
- 没有 commit、tag 或 ADR 时明确写“未创建/无”。
- 路线变化必须先更新规范或 ADR，不能让实施记录单方面改变项目方向。
