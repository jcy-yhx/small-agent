# 阶段规范与状态

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| 未开始 | 尚未获得实施确认，不能编写该阶段代码 |
| 已确认 | 学习者已授权，尚未开始实际修改 |
| 进行中 | 正在实施或验证 |
| 待验收 | 实现完成，但测试、手动验收或文档同步尚未全部完成 |
| 已完成 | 验收全部通过，文档与代码一致，实施记录完整 |
| 阻塞 | 存在无法在当前授权范围解决的问题，原因已记录 |

状态变更必须记录日期和依据。不得因代码“看起来完成”直接标记为已完成。

## 3. 通用阶段契约

每个阶段都必须定义：

- 输入：上一阶段已经提供的能力、确认和资产；
- 输出：本阶段新增代码、文档、测试和可观察结果；
- 依赖：必须完成的阶段和新增外部依赖；
- 正常案例、边界案例和失败案例；
- 至少一个自动化测试和一个手动验收步骤；
- 明确的完成标准和当前能力边界；
- 文件、接口、依赖和数据结构变化；
- 从上一阶段迁移的方法；
- Git commit/tag 记录或“未创建”；
- 文档一致性检查结果。

## 4. 阶段详细规范

### 阶段 0：项目初始化与最小 LLM 程序

- 状态：已完成。自动化验收和在线手动验收均已通过。
- 输入：文档准备阶段成果；学习者明确确认；阶段开始时确认供应商和环境工具。
- 依赖：Python 3.11+；建议 uv；官方模型 SDK；pytest。具体选择待确认。
- 输出：最小项目骨架、CLI 输入、一次 LLM 调用、环境变量示例、Fake LLM 或模拟测试。
- 正常案例：普通非空输入得到并打印回复。
- 边界案例：空白输入得到明确提示，不发起请求。
- 失败案例：缺少或无效凭据时安全失败，不泄露 Key。
- 自动化验收：不联网的模拟调用测试可重复通过。
- 手动验收：配置个人环境后完成一次真实调用。
- 完成标准：能解释消息角色、调用流程和为什么它还不是 Agent；不含 Loop、Tool、Memory、RAG、MCP。

### 阶段 1：Agent State 与 Agent Loop

- 状态：已完成（2026-08-25）。
- 输入：阶段 0 的可测试单次 LLM 调用。

- 输出：目标、步骤、Observation、错误、预算、完成状态和显式循环。
- 正常案例：任务在预算内完成。
- 边界案例：最大步数为 1 时正确终止。
- 失败案例：非法结构化决策不会造成无限循环。
- 自动化验收：25 个离线测试通过，五类终止原因均有确定性覆盖。
- 手动验收：真实模型返回合法 JSON，可从公开步骤还原控制流程。
- 完成标准：已满足；完成、主动失败、最大步数、取消和不可恢复错误均能停止。

## 5. 阶段状态更新规则

每完成一个阶段必须：

1. 将状态从“进行中”更新为“待验收”。
2. 运行正常、边界、失败、自动化和手动验收。
3. 新增 `stages/stage-XX.md` 并填写全部变化。
4. 更新当前架构和故障记录，必要时新增 ADR。
5. 记录 Git commit/tag 或明确未创建。
6. 完成文档与代码一致性检查。
7. 只有全部通过后才能标记“已完成”。
8. 标记后停止，等待下一阶段确认。
