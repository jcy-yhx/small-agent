# 产品需求文档

## 1. 项目概述

Small Agent 是一个面向 AI Agent 初学者的渐进式教学项目。项目从最小 LLM 命令行程序开始，在同一代码库中逐阶段加入状态、循环、工具、记忆、检索、规划、MCP、多 Agent、评估和工程可靠性。

项目首先是学习载体，其次才是可复用框架。所有抽象都必须由当前阶段的实际问题驱动。

## 2. 目标用户

- 能阅读基础 Python，但尚未系统实现过 AI Agent 的学习者；
- 希望理解 Agent 底层机制，而不只是调用成熟框架的人；
- 希望通过测试、日志和安全边界把教学 Demo 逐步工程化的人。

## 3. 产品目标

完成项目后，学习者应能：

1. 实现并解释一次 LLM 调用。
2. 实现 State → Decide → Act → Observe → Update → Stop/Continue 循环。
3. 区分 Function Calling、Tool Calling 和 Tool Execution。
4. 为工具提供 Schema、校验、权限、执行和错误边界。
5. 区分聊天历史、短期记忆、长期记忆和 RAG。
6. 实现带来源的本地知识库问答及基础检索评估。
7. 选择并实现合适的 Planning 模式。
8. 实现 MCP Client、Server 和 Agent 工具适配。
9. 设计最小且可终止的 Multi-Agent 协作。
10. 用测试和评估判断任务是否完成。
11. 提炼小型 Agent Runtime，并理解其与成熟框架的映射。
12. 加入日志、预算、权限、恢复和 Human-in-the-loop 等工程能力。

## 4. 非目标

- 不追求最快生成一套完整 Agent 代码。
- 不在早期构建通用多模型 Provider 框架。
- 不把项目宣称为可直接用于关键业务的生产级平台。
- 不实现 Web UI、移动端或复杂分布式部署，除非未来另立需求。
- 不要求或保存模型完整隐藏思维链。
- 不用 Prompt 替代代码级权限控制。
- 不把 LangChain、LangGraph、AutoGen、CrewAI 等框架作为早期核心实现。
- 不自动提交、推送或创建远程 Git 仓库。

## 5. 功能范围

### 5.1 计划中的最终能力

- LLM 调用与 Prompt 管理；
- 结构化输出、Agent State 和 Agent Loop；
- Function Calling、工具执行和 Tool Registry；
- 低风险及有副作用工具的安全控制；
- Short-term Memory、Long-term Memory 和上下文管理；
- Embedding、向量检索和 RAG；
- Reasoning、Planning、ReAct 和 Plan-and-Execute；
- MCP Client、MCP Server 和能力发现；
- Multi-Agent 协作；
- 日志、错误分类、Token/成本预算；
- 测试、评估、Human-in-the-loop 和可恢复执行；
- 小型 Agent Framework。

以上均为最终目标，不代表当前已经实现。当前实现状态见 `stage-specification.md`。

### 5.2 当前范围

当前已完成阶段 0：最小命令行 LLM 程序、离线测试和硅基流动真实模型手动验收均已通过。Agent Loop、工具、记忆、RAG、规划、MCP 和 Multi-Agent 仍未实现。

## 6. 教学与实现约束

- Python 3.11 或更高版本。
- 命令行作为主要交互方式。
- 建议使用 uv；若实际环境不支持，可经记录后改用 venv + pip。
- 使用环境变量保存本地 Secret，并在需要时提供 `.env.example`。
- 优先使用模型厂商当前官方 Python SDK。
- 结构化数据建议使用 Pydantic 或等价校验方式。
- 使用 pytest 编写自动化测试。
- 基础持久化优先使用 SQLite。
- RAG 阶段才引入 Embedding 和向量检索组件。
- MCP 阶段实现前重新核对官方规范与官方 SDK。
- 同步代码起步，确有并发或协议需要时才引入异步。
- 每阶段只增加少量核心能力，完成后必须仍可运行。
- 阶段开发必须在学习者明确确认后开始。

## 7. 安全边界

- API Key 不写入源码、测试、日志、文档、提交历史或模型上下文。
- 文件工具必须限制在明确工作区并防止路径穿越和符号链接绕过。
- Shell 工具必须采用允许列表、超时、输出限制和参数化执行策略。
- 网络访问必须限制目标、方法、超时、响应大小和敏感信息发送。
- 高风险或不可逆操作必须由人确认。
- 模型输出一律视为不可信输入，执行前进行 Schema、权限和预算校验。
- 外部文档、工具结果、Memory 和 MCP Server 均可能包含恶意内容。
- Agent 必须具有步数、时间、Token、成本或重试上限，避免失控。

完整规范见 `security-guidelines.md`。

## 8. 质量属性

- 可理解：初学者能将概念映射到当前代码。
- 可运行：每阶段均有离线验证，必要时有真实模型手动验证。
- 可测试：正常、边界和失败案例可重复执行。
- 可追踪：后续阶段能通过结构化日志还原外部可观察的执行过程。
- 可恢复：文档足以支持另一位开发者或 AI 继续开发。
- 可演进：新抽象只在重复需求出现时建立。
- 安全默认：无明确授权时拒绝副作用和越权操作。

## 9. 最终完成标准

项目只有在以下条件同时满足时才算完成：

- 阶段 0～13 均已通过各自验收标准；
- 所有自动化测试和定义的安全测试通过；
- 固定评估集具有可复现的结果和明确阈值；
- 当前架构、阶段状态、阶段记录和实际代码一致；
- 能用外部结果证明 Agent 完成任务，而非相信模型自述；
- 工具、记忆、RAG、MCP 和 Multi-Agent 的概念边界有代码实例支撑；
- 项目具备最小权限、预算、审计、错误处理和恢复能力；
- README、配置示例、依赖锁、故障记录和 ADR 足以支持重新搭建与接手；
- 明确列出仍不适合生产使用的部分。

## 10. 待确认项

以下事项尚未成为既定事实：

- 阶段 12 是否需要正式的多供应商 Provider 抽象；
- 是否使用 uv，或因环境限制改用 venv + pip；
- RAG 阶段使用哪种 Embedding 和向量存储实现；
- MCP 阶段采用的官方 SDK 版本和同步/异步方式；
- 阶段 12 是否制作成熟框架迁移分支；
- 各阶段是否实际创建建议 Git tag。

待确认项只能通过学习者确认或 ADR 决策转为既定方案。
