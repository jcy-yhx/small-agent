# ADR-0002：当前环境使用 venv 与 pip

- 状态：已接受
- 日期：2026-08-25
- 决策者：当前阶段实现确认
- 相关阶段：stage-00
- 取代：无
- 被取代：无

## 背景

路线图建议使用 uv，在环境不适合时允许使用 venv + pip。阶段 0 检查发现 Python 3.14.4 可用，但系统中不存在 uv。为避免在课程实现之外额外安装全局工具，采用标准库 venv 和 pip。

## 候选方案

### 方案 A：安装并使用 uv

- 优点：项目与依赖管理体验统一，锁定能力完善。
- 缺点：当前系统没有该工具，需要额外引导或全局安装。

### 方案 B：使用 venv + pip

- 优点：当前 Python 自带 venv，能立即创建隔离环境。
- 缺点：项目清单和完整锁定文件需要共同维护。

## 决策

当前使用 `.venv + pip`。直接依赖固定在 `pyproject.toml`，经验证的完整环境固定在 `requirements.lock`。

## 后果

- 新环境可按根目录 README 重建。
- 每次依赖变更必须同步项目清单和 `requirements.lock`。
- 若未来迁移到 uv，必须新增 ADR 并统一更新命令，不能长期维护两套冲突说明。

## 验证方法

- 在 `.venv` 中完成 editable 安装。
- `pip check` 无依赖冲突。
- 全部测试在隔离环境中通过。

## 回滚或迁移方案

学习者确认安装 uv 后，可创建取代本记录的新 ADR，并由 uv 重新生成其原生锁文件。
